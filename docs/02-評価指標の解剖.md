# 評価指標の解剖 — cell-eval のソースから読み取れること

本ドキュメントの内容は推測ではなく、`cell-eval` 0.8.2 の実装
(`cell_eval/_score.py`, `_pipeline/_runner.py`, `metrics/_anndata.py`,
`_evaluator.py`, `_cli/_prep.py`) を読み、実際に動かして確認したものです。

## 1. 集約スコアの形

`score_agg_metrics` の実装:

```
低いほど良い指標 (mae, mse, …):  s = 1 - user / base
高いほど良い指標 (PDS, DES, …):  s = (user - base) / (1 - base)
s = clip(s, 0, None)              ← ここが重要
avg_score = mean(s)
```

`base` は「全摂動に対して **コントロール平均** を予測するモデル」
(`cell_eval/_baseline.py: build_base_mean_adata`)。

### 戦略的な帰結

**負け指標は 0 で止まる。** ベースラインに負けた指標の寄与はちょうど 0 であり、
どれだけ悪くてもそれ以上は減らない。一方で勝てる指標は青天井に伸びる。

したがって「MAE を守るために delta を縮める」という 2025 でよく見られた
判断は、**すでに MAE で負けている領域では純粋な損** になる。
2025 では全チームが MAE でベースラインに勝てず事実上除外されていた。
効果量スケール `alpha` は MAE 最適点ではなく **集約スコア最適点** に置くべきで、
本リポジトリではその差を実測できるようにしてある（`vcc.calibrate.sweep`）。

シミュレータ上の alpha スイープ（`scripts/benchmark_synthetic.py`）:

| alpha | mae | PDS | avg_score |
|---|---|---|---|
| 0.2 | 0.056 | 0.415 | 0.372 |
| 0.6 | 0.139 | 0.887 | 0.479 |
| 0.8 | 0.161 | 0.928 | 0.493 |
| 1.0 | **0.165** | 0.944 | **0.497** |
| 1.2 | 0.144 | 0.952 | 0.491 |
| 1.5 | 0.080 | 0.960 | 0.471 |
| 2.0 | 0.000 | 0.957 | 0.444 |

MAE を捨てても PDS が伸びる限り集約スコアは上がり続ける。この掃引では
両者の最適点がたまたま近いが、実データではずれるほうが普通で、
そのときは **MAE ではなく集約スコアに従う**。

## 2. 指標は「疑似バルク」で計算される

`metrics/_anndata.py` の `_generic_evaluation` / `discrimination_score` は
すべて `iter_bulk_arrays()`、つまり **摂動ごとの細胞平均** の上で動く。

- MAE / MSE / pearson_delta / PDS は、細胞レベルのばらつきに**一切依存しない**
  （平均さえ保てば自由）。
- DE 系指標 (`overlap_at_N`, `precision_at_N`, `de_direction_match`, …) だけが
  実際に細胞レベルの DE 検定 (pdex) を回すので、ばらつきに依存する。

→ **平均を正確に保ったまま、ばらつきだけを自由に設計できる。** 本実装の
`CellSampler` はこの性質を使い、応答倍率 `r_i` の平均をちょうど 1 に正規化して
疑似バルク平均を予測値と厳密に一致させている（`vcc/sampler.py`）。

## 3. PDS は標的遺伝子を除外する

`discrimination_score(..., exclude_target_gene=True)`。オンターゲット
ノックダウンをどれだけ正確に当てても **PDS には 1 ビットも効かない**。
PDS はトランス効果だけの勝負。

さらに PDS は「予測 delta が、全摂動の実測 delta の中で自分の実測 delta に
最も近いか」を L1 距離の順位で測る。18k 次元の L1 距離は**効果量に支配される**。
全摂動の delta を一律に小さく予測すると、どの摂動も「最も弱い実測摂動」に
マッチしてしまい、順位が総崩れになる。**摂動ごとの効果量の当て方が、
方向の当て方と同じくらい重要。** 本実装の `magnitude_gamma` はここに効く。

## 4. 実測で見つかった 2 つの落とし穴

どちらも生物学ではなく実装の問題だが、スコアへの影響は生物学より大きかった。

### 4.1 正規化スケール — MAE を 13 倍悪化させる

`_convert_to_normlog` は `scanpy.pp.normalize_total(adata)` を
**`target_sum` を渡さずに** 呼ぶ。scanpy のデフォルトは 1e4 ではなく
**そのデータの中央値ライブラリサイズ**。つまり参照データの絶対スケールは
シーケンス深度で決まる。

慣例どおり `target_sum=1e4` で normlog した提出物は、実測データと違う軸に乗る。
同一の予測を `--target-sum 10000` と既定（中央値）で出し分け、
公式スコアリング経路 (`cell-eval baseline` → `run` → `score`) で測った結果:

| | MAE | MSE | mae スコア | mse スコア | **avg_score** |
|---|---|---|---|---|---|
| 1e4 スケール | 0.6474 | 0.5106 | 0.000 | 0.000 | 0.3106 |
| 中央値スケール | **0.0482** | **0.0047** | 0.121 | 0.391 | **0.3955** |

生物学的予測は 1 ビットも変えずに MAE が 13 倍、MSE が 109 倍改善し、
集約スコアが 27% 上がる。PDS (0.976 → 0.972) と pearson_delta (0.663 → 0.666) は
スケール不変なので動かない — 損失はすべて絶対値指標に集中する。

対策: 提出値は **対象細胞株のコントロール細胞の中央値ライブラリサイズ** で
normlog する（同じ実験・同じ深度なので、参照データのスケールの最良推定）。
本実装のデフォルト。`tests/test_end_to_end.py` に cell-eval の実装そのものと
突き合わせる回帰テストを置いてある。

### 4.2 疑似バルク平均の再サンプリングノイズ

摂動細胞をコントロールプールからリサンプルして作ると、その部分集合の平均が
プール全体の平均からずれる。このずれは疑似バルク平均にそのまま乗り、
MAE と pearson_delta に課金される。ベースライン（全コントロール細胞の平均）は
このノイズを払っていないので、一方的に不利になる。

対策: 各アーム（摂動アーム・コントロールアーム）の平均を、
サンプルした部分集合ではなく **コントロールプール全体の平均 + 予測 delta** に
厳密に合わせ込む。非負制約を壊さないよう、平均を上げる方向はシフト、
下げる方向はスケールで補正する（`CellSampler._match_mean`）。

シミュレータ上での実測（`cell-eval` 公式スコアリング経路）:

| 指標 | 修正前 | 修正後 |
|---|---|---|
| avg_score | 0.2435 | **0.3955** |
| mae | 0.000 | 0.121 |
| overlap_at_N | 0.025 | 0.244 |
| pearson_delta | 0.294 | 0.534 |
| mse | 0.132 | 0.391 |
| discrimination_score_l1 | 0.920 | 0.929 |

モデルを一切触らずに集約スコアが +62%。

## 5. 6 指標パネルの推定

2026 の 6 指標は 2026-08 時点で cell-eval の公開版に入っていない
（`VCC_METRICS` は 2025 の 3 指標のまま）。レジストリに登録済みの 27 指標と
2025 の Generalist 賞（7 指標）から、有力なのは:

`mae` / `discrimination_score_l1` (PDS) / `overlap_at_N` (DES) /
`pearson_delta` / `de_direction_match` / `pr_auc` あるいは `de_spearman_lfc_sig`

本実装の `vcc.localeval.PANEL` はこの想定で組んであり、正確な 6 指標が
判明したら差し替えるだけで済む。**最終的な数値は必ず `cell-eval run` で確認する**
（`scripts/score_with_cell_eval.sh`）。localeval は掃引を回すための高速な代用品。

## 6. 提出フォーマットのチェックリスト

`cell_eval/_cli/_prep.py` から:

- `obs['target_gene']`（摂動名）が必須。コントロール名は `non-targeting`。
- 複数細胞株なら `obs['celltype']` を付けて `--celltype-col celltype`。
- `var_names` は配布された遺伝子リストと **完全一致・同順**。
- 細胞数上限 `MAX_CELL_DIM = 200000`、遺伝子数 `EXPECTED_GENE_DIM = 18080`
  （2025 の値。2026 で変わる可能性があるので配布ファイルで確認すること）。
- `tar` と `zstd` が PATH に必要。
- `vcc.submit.validate()` がこれらを提出前に全部チェックする。
