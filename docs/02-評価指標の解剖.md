# 評価指標の解剖 — 2026 の実スコアラー

> **2026-08-24 改訂。** 本ドキュメントの初版は `cell-eval` 0.8.2（2025 版）の
> 実装を読んで書いたもので、**2026 の実スコアラーとは挙動が違う部分があった**。
> API キーで CLI と実データにアクセスできるようになったため、公式ドキュメントと
> 実データで確認した内容に全面的に差し替えている。旧版の誤りは §5 に明記した。

## 1. 6 指標と集約

`vcc submit --wait` が返す 6 指標（括弧内はリーダーボードの列名）:

| 指標 | 内容 |
|---|---|
| Perturbation discrimination (`pds`) | 予測した効果が「自分の」摂動に最も近いか |
| Expression accuracy (`mse`) | 発現量そのものの精度 |
| DE log-FC accuracy (`nmae`) | 差次発現の log fold change の精度 |
| DE direction fidelity (`fid`) | 差次発現の向きの正しさ |
| DE direction reach (`reach`) | 向きの正しさが届く範囲 |
| DE significance overlap (`jac`) | 有意遺伝子集合の重なり（Jaccard） |

**Overall = この 6 つの単純平均**（重み付けなし）。

### スケールの意味

- **0 = 細胞文脈平均ベースライン**（全摂動に「その文脈の平均細胞」を貼るのと同じ）
- **1 = 実験データの split-half replicate**（実データの半分がもう半分を予測する精度）

`1.0` は上限ではなく**目印**。replicate は実験ノイズを含むので、完璧な予測は
多くの指標で 1 を超える。上限があるのは `mse` のみ。

**下限は指標ごとに違い、0 ではない**:

| 指標 | 下限 |
|---|---|
| `mse` | 0（ここだけ 0 で止まる） |
| `nmae` | −6（ペナルティ上限） |
| `fid` | 約 −1.9 |
| `jac` | 約 −0.1 |
| `pds`, `reach` | それぞれの深さまで |

## 2. これが戦略に与える最大の帰結

**確信のない予測は「文脈平均を出す」のが最適。** 文脈平均はその摂動で
ちょうど 0 を取り、負にはならない。一方、自信を持って間違えた予測は
`fid` で −1.9、`nmae` で −6 まで落ちうる。

つまり **効果量スケールを上げる判断には実在のダウンサイドがある**。
確信度に比例して文脈平均へ縮小させるのが正しい姿勢で、
本実装の信頼度ブレンド `b` と大域スケール `alpha` はそのためにある。

## 3. スコアは条件付きでしか読めない

出力末尾の 3 行（`Partition` / `Panel` / `Anchor set`）が**スタンプ**で、
どの分割・どの摂動パネル・どのスケーリング基準で出た数字かを示す。
`Anchor set` は文脈ごとに 1 バンドル（各文脈が自分の 2 基準点でスケールされる）。

**検証フェーズ（A/B/C）と最終フェーズ（D/E/F）のスコアは比較できない。**
細胞株が違い、摂動パネルが違い、指標のひとつはパネル内の順位だから。
最終スコアが検証より低くても、モデルが悪化したわけではない。

## 4. 文脈ラベルの取り違えが最も高くつく間違い

セルに付いた `context` ラベルが、どの held-out データと比較されるかを決める。
A と B を入れ替えると全指標が偶然レベルに落ちるが、**スコアには「ラベルを
間違えた」とはどこにも書かれない**。弱いモデルにしか見えない。

`vcc prep` は 3 文脈が揃っていることと未知ラベルがないことは検査するが、
**A と B が入れ替わっていることは検出できない**。

本実装では `Bundle` がコントロールファイル名と中身の `context` 列の一致を
検証し、不一致なら推測せずに落ちる（`vcc/challenge.py`）。最終フェーズで
A/B/C を持ち越さないよう、ラベルは常にバンドルから読む。

## 5. 旧版（2025 版 cell-eval を読んで書いた内容）の誤り

初版には次の記述があったが、**2026 には当てはまらない**。

| 旧版の記述 | 実際 |
|---|---|
| 「負け指標は 0 でクリップされるので、悪化してもコストはない」 | **誤り。** それは 2025 版 `score_agg_metrics` の挙動。2026 は `mse` 以外に 0 の床がなく、負の値が集約に効く |
| 「MAE を捨てて他に全振りするのが正解」 | **誤り。** 上と同じ理由。捨てた指標が負を出して足を引っ張る |
| 提出は normlog、スケールは中央値ライブラリサイズ | **提出は raw counts。** 2026 は counts 空間で採点し、小数を含む行列は即リジェクト |
| `celltype` 列 | **`context` 列**（A/B/C、最終は D/E/F） |
| 遺伝子数 18,080 / 上限 200,000 細胞 | **18,533 遺伝子 / 400,000 細胞上限** |
| 提出にコントロール細胞を含める | **含めるとリジェクト。** 採点は held-out のコントロールを使う |

「正規化スケール」の発見（`normalize_total` の `target_sum` 既定が中央値
ライブラリサイズであること）自体は正しく、シミュレータ上で MAE 13 倍・
集約スコア 27% の差として実測もした。ただし **2026 の提出物は raw counts** なので、
提出パスにこの落とし穴は存在しない。内部で normlog を使う箇所（転移演算子、
共発現特徴）では依然として正しい注意点。

## 6. 提出フォーマット（実測・実仕様）

`vcc prep` と採点側が検査する項目。すべて `vcc/submission.py` が構成上満たす。

| 項目 | 値 |
|---|---|
| 形式 | 単一 `.vcc`（3 文脈すべてを 1 ファイルに） |
| 摂動 | `pert_counts.csv` と完全一致（300 個、過不足なし）。遺伝子シンボル、構築 ID ではない |
| 細胞数 | 各摂動 **ちょうど 400 細胞**、各文脈で。1 個ずれてもリジェクト |
| 遺伝子 | **18,533** 個すべて。順序は prep が直す |
| 値 | **raw counts**（非負の整数値。float 格納は可） |
| 細胞あたり上限 | 1,000,000 counts |
| 総細胞数上限 | 400,000（本パネルは 360,000） |
| 密度上限 | 4,750,000,000 stored entries（≈13,200/細胞）。**dense 保存は単体で超過** |
| コントロール細胞 | **含めるとリジェクト** |

実測値: 本実装の提出物は 1 細胞あたり約 5,930 stored entries で、
360,000 細胞なら約 2.13e9 — 上限の 45%。gzip 圧縮で約 4.8 GB。

## 7. 提出運用

- 1 日あたりの提出数に上限があり、UTC 深夜にリセット。
  **採点に到達した提出だけが消費される**（フォーマットエラーや 409 は無料）。
- チームで**同時に走らせられる提出は 1 つ**。2 つ目は HTTP 409。
- アップロード中断は `vcc submit <file> --resume` で再開。

したがって掃引は「1 日に数点」しか回せない。オフラインの検証
（2025 公開データでの leave-one-out）で候補を絞ってから投げる必要がある。
