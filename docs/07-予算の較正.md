## 9c. 予算 K は、シミュレーションではなく排出して測る

`strategy_search` は「宣言した集合がそのまま採点される」と仮定するが、
実際には**排出した細胞が Wilcoxon 検定を通った分しか宣言にならない**。
較正パネル（47 摂動）で、target 固有信号・margin 1.15 のまま K を振り、
毎回セルを排出して `cell_eval2` の DE を回した結果:

| K | 実現 n_pred（中央） | fid | reach | jac | nmae | mean6 |
|---|---|---|---|---|---|---|
| 1,000 | 578 | 0.4876 | 0.1507 | 0.0291 | 0.9740 | +0.008 |
| 2,000 | 1,403 | 0.5267 | 0.1210 | 0.0320 | 0.9778 | +0.025 |
| **3,000** | **2,243** | 0.5242 | **0.1612** | 0.0322 | 0.9646 | **+0.035** |
| 5,000 | 4,205 | 0.5200 | 0.1218 | 0.0294 | 0.9638 | +0.024 |

**実現 n_pred は K の 70〜84% にしかならない。** margin 1.15 は
「半分が有意になる」しきい値の 1.15 倍なので、当然そうなる。
シミュレーションが K=2,000 を最適と言ったのはこのズレを見ていないから。

K=1,000 で `fid` が 0.4876（偶然を下回る）まで落ちるのは被覆項のせい。
`n_real` が 1,000 を超える摂動では `min(1, n_pred/n_real)` が効いて、
方向が当たっていても割り引かれる。

`reach` が K=3,000 で跳ねる（0.121 → 0.161）のは、
呼び出し集合の**中身**ではなく**順序**の問題。p 値が同点（p_adj ≈ 0）に
潰れた塊のなかは |lfc| の降順で並び、|lfc| は発現量の逆数なので
**低発現の遺伝子が先頭に来る**。K が大きすぎると先頭が低発現で汚れ、
小さすぎると母数 `n_real` に対して浅いところで止まる。

## 9d. 転移モデルのハイパーパラメータは方向を動かさない

`fid`・`reach`・`pds` はすべて「方向が当たるか」に帰着するので、そこを直接
目的関数にして CCDT のノブを総当たりした（較正パネル 47 摂動、
順位付けは呼ばれやすさ × |delta|、上位 d 遺伝子での方向一致率）。

| 振ったもの | 範囲 | 上位 50 での一致率 |
|---|---|---|
| STRING しきい値 | 150 / 400 / 700 | 0.558〜0.571 |
| 近傍数 | 25 / 100 / 400 | 0.558〜0.571 |
| 近傍重みの指数 | 1 / 2 / 4 | 0.558〜0.571 |
| 低ランクプログラム数 | 25 / 50 / 100 / 200 / 400 | 0.568〜0.573 |
| 共有成分の縮小 | 0.0 / 0.25 / 0.5 | **0.554〜0.573** |

**唯一はっきり効いたのは共有成分の縮小で、しかも効き方は「入れると悪くなる」**
（0.5 で 0.019 落ちる）。既定の 0.0 のままでよい。残りはどれも差が 0.005 以下で、
d1000 以降ではほぼ完全に一致する。

つまり**方向の的中率 0.52〜0.57 はチューニングで動く量ではない**。
遺伝子どうしの類似度を STRING の近傍プロファイルで測っていることそのものが
効いていて、次に試すべきは別の遺伝子表現（タンパク質埋め込みなど）か、
別の転移演算子。

## 10b. パネル平均を引くと `pds` が伸びる

`pds` は「予測どうしがどれだけ違うか」を読む指標で、方向の的中率とは別の目的関数。
`shared_shrink`（全 target の平均を各予測から引く）を振って、
手元のリファレンスの疑似バルク効果に対する `pds` を直接測った:

| `shared_shrink` | `pds` |
|---|---|
| 0.00 | 0.5904 |
| 0.25 | 0.6017 |
| 0.50 | 0.6065 |
| 0.75 | 0.6336 |
| **1.00** | **0.6506** |

単調に伸びる。生値 +0.060 は scaled で +0.13、Overall で +0.022 に相当する。

方向の的中率への影響も、実際に宣言する集合の形（上位 3,000、大きさは有意しきい値）
で測りなおすと小さい:

| 順位付け / 符号 | `pds` | 上位 50 の方向 | 上位 1,000 の方向 |
|---|---|---|---|
| 素 / 素（v11） | 0.5856 | 0.500 | 0.524 |
| **引く / 引く** | **0.6455** | 0.513 | 0.508 |
| 引く / 素 | 0.6073 | 0.515 | 0.515 |
| 素 / 引く | 0.6260 | 0.508 | 0.514 |

「引く/引く」が `pds` で最良、方向も上位 50 では素より良く、
上位 1,000 で 0.016 落ちるだけ。方向の掃引（9d）で `shared_shrink` が
悪化要因に見えたのは、順位付けを `呼ばれやすさ × |delta|` で測っていたからで、
**実際に排出される順序で測ると差はほとんどない**。

ついでに分かったこと: 排出した `|lfc|` の降順で見た方向の的中率は **0.500**、
つまり完全に偶然。`reach` が同点ブロックの中でこの順序を使う以上、
そこは何の情報も持っていない。
