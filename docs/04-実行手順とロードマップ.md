# 実行手順と締切までのロードマップ

## セットアップ

```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[eval,dev]'
.venv/bin/python -m pytest tests -q          # 13 tests, データ不要
sudo apt-get install -y zstd                 # cell-eval prep が tar と zstd を要求する
```

チャレンジデータなしで全体が動くことの確認:

```bash
.venv/bin/python scripts/benchmark_synthetic.py
```

## 実データでの実行

### 1. 公開データの取得

```bash
scripts/download_public_data.sh data/     # VCC 2025 (H1) は完全公開
```

2026 の検証／テストデータは <https://virtualcellchallenge.org/> の
登録アカウント経由でのみ配布される（公開 GCS バケットには 2025 しかない）。
ダウンロードして `data/vcc2026/` に置く。

Replogle の K562 / RPE1 は Arc Virtual Cell Atlas から取得し、
`obs` の摂動列を `target_gene`、コントロール名を `non-targeting` に
揃えてから使う（`--pert-col` / `--control-name` で別名も指定可）。

### 2. シグネチャライブラリの構築（1 回だけ）

```bash
.venv/bin/python scripts/build_library.py \
  --genes data/vcc2026/gene_names.csv \
  --source H1=data/vcc2025/adata_Training.h5ad \
  --source K562=data/replogle/K562.h5ad \
  --source RPE1=data/replogle/RPE1.h5ad \
  --out outputs/library.npz
```

各ソースは 1 回ストリームされ、摂動あたり 1 本の疑似バルクベクトルに潰される。
細胞数がいくら増えてもキャッシュは数百 MB で収まり、以降は生 h5ad に触らない。

### 3. 予測と提出物の生成

```bash
.venv/bin/python scripts/predict.py \
  --library outputs/library.npz \
  --genes data/vcc2026/gene_names.csv \
  --context all=data/vcc2026/adata_Validation.h5ad --celltype-col celltype \
  --pert-counts data/vcc2026/pert_counts_Validation.csv \
  --out outputs/submission.h5ad --prep
```

`outputs/submission.prep.vcc` をリーダーボードにアップロードする。

> 配布ファイルの実際のレイアウト（細胞株が 1 ファイルにまとまっているか、
> 株ごとに分かれているか）は 2026 の配布物で確認すること。`--context` は
> 繰り返し指定できるので、株ごとのファイルなら `--context HEK293T=... --context K562=...`。

### 4. ローカル検証（実測ラベルがある場合）

```bash
scripts/score_with_cell_eval.sh outputs/submission.h5ad data/real.h5ad outputs/score
```

これが公式と同じ経路（`cell-eval baseline` → `run` → `score`）。
掃引を回すときだけ `vcc.localeval` の高速版を使い、報告値は必ずこちらで取る。

## 締切までのロードマップ（2026-11-05 23:59 UTC）

現在は検証フェーズ（2026-08-20 開始）。最終テストは 10-22 公開、投稿は 11-05 まで。

### フェーズ 1: 足場固め（〜8 月末）

1. 2026 検証データを取得し、配布フォーマットを確認して `predict.py` の
   `--context` / `--pert-counts` の読み方を実データに合わせる。
2. **まず提出する。** どんなに粗くてもいい。リーダーボードの数値が出るまで、
   6 指標の実際の重み付けは分からない。
3. `EXPECTED_GENE_DIM` と `MAX_CELL_DIM` を配布ファイルで確認
   （2025 の 18080 / 200000 から変わっている可能性がある）。

### フェーズ 2: 検証済みの実装レバー（9 月上旬）

`docs/02` の 2 つの落とし穴は実測で効果を確認済み。実データでも最初に潰す。

4. `--target-sum` を 2〜3 点掃引して、中央値スケール推定が正しいことを
   リーダーボード上で確認する。**投資対効果が最も高い実験**（MAE 13 倍、集約スコア +27%）。
5. `alpha` を 0.6 / 0.8 / 1.0 / 1.3 で掃引。集約スコアの最適点は
   MAE 最適点より大きい側にあるはず。
6. `magnitude_gamma` を 0 / 0.5 / 1.0 で掃引（PDS に直結）。

### フェーズ 3: モデルの中身（9 月中〜10 月中）

7. **DE 系指標の改善** — シミュレータで最も弱い部分。予測有意遺伝子数を
   実測に合わせるところから。`non_responder_fraction` と `response_shape`、
   および摂動あたりの出力細胞数が効く。
8. **ソースの追加** — 細胞株の多様性が転移の質を直接決める。Replogle の
   HepG2、Tahoe-100M（薬剤だが文脈は 50 株ある）、社内スクリーンがあれば全部。
   ソースが 3 株から 6 株に増えたときの LOCO スコアの伸びを測る。
9. **ESM2 埋め込みの投入** — 2025 の上位 2 チームが揃って有効と報告。
   `--embeddings` に `.npz` を渡すだけ。未観測標的の予測精度で効くはず。
10. **6 指標が判明したら `localeval.PANEL` を差し替える**。

### フェーズ 4: 最終提出（10-22 〜 11-05）

11. 最終テストセット公開後、ハイパーパラメータは **検証フェーズで固定したものを
    そのまま使う**。最終セットでの調整は 3 株分のリーダーボードフィードバックが
    ないので、過剰適合しかしない。
12. 締切の 48 時間以上前に提出する。`cell-eval prep` の失敗（遺伝子順、細胞数上限、
    `zstd` 不在）は当日に発見すると致命的。`vcc.submit.validate()` を必ず通す。

## リスクと打ち手

| リスク | 打ち手 |
|---|---|
| 6 指標の内訳が想定と違う | localeval はパネル差し替え式。公式値は必ず `cell-eval run` で取る |
| 2026 の配布フォーマットが想定と違う | I/O は `submit.py` / `context.py` に隔離済み。読み替えはそこだけ |
| ソース細胞株が足りず転移が効かない | LOCO で株数とスコアの関係を測り、データ追加の費用対効果を判断 |
| 検証 3 株への過剰適合 | ハイパーパラメータは LOCO と検証リーダーボードの **両方** で一致するものだけ採用 |
| MAE がどうしても勝てない | 集約は 0 でクリップされるので、その場合は MAE を捨てて他 5 指標に全振りするのが正解 |
