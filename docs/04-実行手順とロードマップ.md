# 実行手順と締切までのロードマップ

締切 **2026-11-05 23:59 UTC**。最終テストセット公開 10-22。現在は検証フェーズ。

## セットアップ

```bash
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
python3 -m venv .venv-cli && .venv-cli/bin/pip install vcc-cli
.venv/bin/python -m pytest tests -q      # 27 tests、チャレンジデータ不要
```

公式 CLI を別 venv に入れる理由: 配布名 `vcc` が公式 CLI のもので、
本パッケージ `vcc2026` と衝突する（同居させると `vcc` コマンドが壊れる）。

## 実行

```bash
export VCC_TOKEN=<key>                       # headless 環境では keyring を使わずこれ
.venv-cli/bin/vcc whoami                     # "ready to submit" を確認
.venv-cli/bin/vcc datasets download controls -d data/vcc
cd data/vcc && unzip -o vcc_2026_controls.zip
```

転移元ライブラリ（公開データを疑似バルク化。生 h5ad は使い捨てでよい）:

```bash
.venv/bin/python scripts/build_library_2025.py \
  --genes data/vcc/gene_names.csv \
  --source H1=data/vcc2025/adata_Training.h5ad \
  --out out/lib_h1.npz
```

STRING ネットワーク（遺伝子類似度。GPU も学習も不要）:

```bash
curl -O https://stringdb-downloads.org/download/protein.links.v12.0/9606.protein.links.v12.0.txt.gz
curl -O https://stringdb-downloads.org/download/protein.info.v12.0/9606.protein.info.v12.0.txt.gz
# vcc2026.network.load_string_network(...) で adjacency を作り save_npz
```

予測 → パッケージ → 提出:

```bash
.venv/bin/python scripts/predict_vcc2026.py \
  --bundle data/vcc --out out/sub.h5ad --vcc out/sub.vcc \
  --library out/lib_h1.npz --string-adj out/string_adj.npz \
  --trans-similarity-floor 0.1

.venv/bin/python -c "..."                     # vcc2026.validate.validate_submission
.venv-cli/bin/vcc submit out/sub.vcc -m "..." --wait
```

`vcc prep` はこの環境では動かない（`docs/05 §7`）。`.vcc` は直接生成し、
本物の prep との一致は `tests/test_vcc_parity.py` が保証する。

## 提出の制約

- 1 日あたりの提出数に上限、UTC 深夜リセット。**採点に到達した提出だけが消費**される
  （フォーマットエラーや 409 は無料）。
- チームで同時進行できる提出は **1 つ**。
- 1 サイクルの実時間: ビルド 17 分 + パッケージ 1 分 + アップロード 10 分 + 採点 10〜25 分。
  **1 日に回せるのは数回**。オフライン検証で候補を絞ってから投げること。

## 優先順位（実測に基づく）

### 1. 排出モデルの忠実性 — 済み、最大の効果

初回提出の損失の大半は生物学ではなく排出モデルのアーティファクトだった
（`docs/05 §2, §3`）。**モデルを触る前に、予測ゼロなら排出が恒等写像になることを
確認する。** `scripts/null_emission_test.py` がこれを測る。回帰テストも入っている。

### 2. 遺伝子表現 — ここが本丸

leave-one-out の実測（`docs/05 §5`）:

| 表現 | 平均 r | discrimination |
|---|---|---|
| コントロール細胞の共発現 | 0.165 | 0.509（偶然） |
| 平均署名（何も個別化しない） | 0.188 | 0.500 |
| STRING | 0.235 | 0.584 |
| **oracle（真の署名類似度）** | **0.471** | **0.748** |

oracle との差が、そのまま残っている伸びしろ。試す価値がある順:

1. **測定済み署名を増やす**（下記 §3）。STRING のカーネルより、
   転移元の数の方が効いている可能性が高い — 2026 の標的の
   STRING 最近傍類似度は中央値 0.167 しかなく、150 署名では近傍が薄い。
2. **ESM2 等のタンパク質言語モデル埋め込み**。2025 の上位 2 チームが
   揃って有効と報告。`--embeddings` に npz を渡すだけで入る。
3. **CORUM 複合体 / GO** を STRING と結合。

### 3. 転移元データを増やす

| ソース | 標的数 | 状態 |
|---|---|---|
| VCC 2025 train (H1) | 150 | 取り込み済み |
| VCC 2025 validation (H1) | 50 | 取り込み中 |
| VCC 2025 test (H1) | 100 | 取り込み中 |
| Replogle K562 / RPE1 / HepG2 | 数千 | **未取得。最大の未回収分** |
| Tahoe-100M（薬剤、50 株） | — | 文脈の多様性の唯一の供給源 |

**現状の転移元は 1 細胞株しかない。** 細胞株をまたぐ転移を学習する材料が
そもそも無いので、`transfer.rebase` の乗算仮定は検証できていない。
Replogle（K562/RPE1）を入れると 2 株目が入り、
leave-one-cell-line-out が初めて本物のデータで回せるようになる。

### 4. 効果量の較正 — `pds` の伸びしろは丸ごと残っている

v0 の `pds_cosine` は 0.5057、つまり偶然。この指標はトランス署名の
**効果量**に強く依存する（L1/コサイン距離が大きさに支配される）。
`magnitude_gamma` と `alpha` の掃引はここに効くはずだが、
先にトランス署名そのものが機能する必要がある。

### 5. 最終フェーズ（10-22 以降）

- ラベルは **D/E/F**。A/B/C を持ち越すと全指標が偶然レベルに落ちるが、
  スコアには何も表示されない。`Bundle` がバンドルからラベルを読むので
  コード上は安全だが、**バンドルを取り違えないこと**。
- ハイパーパラメータは検証フェーズで固定したものを使う。最終セットには
  フィードバックがないので、そこでの調整は過剰適合にしかならない。
- 締切 48 時間前には提出を終える。アップロードだけで 10 分、採点に 25 分かかる。
