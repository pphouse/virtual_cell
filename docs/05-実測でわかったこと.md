## 1b. 2 回目の提出（v1）とアンカー値の確定

`entry aRf0AeI4vGwcDphMEiwI` — 排出モデルを修正し、実測残存率 0.148 を使用。

**Overall −0.3035（v0 の −0.0638 より悪化）。** `fid` は −1.7175 で下限付近。

生値を並べると理由は一目瞭然だった:

| 生指標 | v0 | v1 |
|---|---|---|
| `de_wilcoxon_direction_fidelity_yield_raw` | 0.4097 | **0.0023** |
| `de_wilcoxon_sig_jaccard` | 0.0165 | **0.0000** |
| `pds_cosine` | 0.5057 | 0.4910 |

v1 は**有意 DE 遺伝子をほぼ 1 個も出していない**（Jaccard がちょうど 0）。
指標名の "yield" は文字どおりで、方向が正しくても量が無ければ 0 になる。

### アンカー値（2 つの提出から連立方程式で確定）

同じ anchor set 上の 2 点があれば `scaled = (raw − b)/(r − b)` を解ける。

| 指標 | ベースライン `b` | replicate `r` |
|---|---|---|
| `pds_cosine` | **0.5001**（＝完全に偶然） | 0.9698 |
| `de_wilcoxon_direction_fidelity_yield_raw` | 0.5110 | 0.8071 |
| `de_wilcoxon_sig_jaccard` | 0.0302 | 0.3963 |
| `de_wilcoxon_direction_reach_raw` | 0.0785 | 0.9201 |
| `de_wilcoxon_lfc_nmae`（小さいほど良い） | 1.0014 | 0.3805 |

これで**提出せずにスコアを見積もれる**ようになった。

### ここで自分の指標モデルが間違っていたことが分かった

`docs/02` に書いていた「確信のない摂動は文脈平均を出せば 0 で済む、
だから棄権は安全」という理解は **DE 系 4 指標については逆**だった。

- ベースライン（文脈平均を全摂動に貼る）は、細胞間分散がゼロなので
  Wilcoxon 検定が最大の検出力を持ち、**多数の遺伝子を有意と呼ぶ**。
  方向はランダム（`fid` 生値 0.511 ≒ 偶然）だが、量はある。
- 一方 v1 は現実的な分散を持つ実コントロール細胞そのものなので、
  **ほぼ何も有意にならず**、yield がゼロになって下限へ落ちた。

つまり **「何も予測しない」は棄権ではなく、大きな失点**。
DE 系指標で勝つには「多数の遺伝子について、方向を 51% より正しく予測する」
必要がある。効果を小さく見積もる方向の安全策は効かない。

`pds` は別で、ベースラインがちょうど 0.500（偶然）、replicate が 0.970。
**生値レンジ 0.47 が丸ごと手つかず**で、6 指標中もっとも伸びしろが大きい。

## 2. 排出モデルが偽の DE を撒いていた

`scripts/null_emission_test.py`

摂動を一切かけない（fold change = 0）状態で細胞を排出し、
同じ文脈の実コントロール細胞に対して採点側と同じ Wilcoxon 検定をかける。
忠実な排出なら有意遺伝子はほぼ 0 になるはず。

| 排出方式 | 有意遺伝子（11,658 中） | 向き |
|---|---|---|
| 実細胞（真の null） | **0** | — |
| 全遺伝子リサンプル a=0.0 | 5,705 (49%) | 99.8% が DOWN |
| 全遺伝子リサンプル a=0.5 | 82 | 57% が up |
| **全遺伝子リサンプル a=1.0（初回提出）** | **93** | **89% が UP** |
| 全遺伝子リサンプル a=2.0 | 160 | 94% が up |
| **予測した遺伝子のみ更新（修正後）** | **0** | — |
| 修正後 + 1 遺伝子ノックダウン | **1**（その遺伝子だけ、DOWN） | — |

初回提出は、**摂動を予測していない遺伝子に対して、
全 300 摂動 × 3 文脈で同じ向きの偽 DE を約 93 個ずつ**渡していた。
実際のノックダウン応答は down が優勢なので、これだけで方向一致率が
偶然を下回る。`fid = −0.34` の正体。

> **補足（v1 の結果を受けて）。** この修正自体は正しい — v0 の
> `fid` 生値 0.41 はベースライン 0.511 を下回っており、89% が UP の
> アーティファクトが実際の down 優勢な応答と反相関していた。
> ただし修正だけでは足りなかった。**アーティファクトを消すと同時に、
> 本物の DE 予測でその量を埋めなければ yield がゼロになる。**
> v1 はその後者を欠いていた。

### なぜ較正をすり抜けたか

排出モデルの平滑化パラメータは当初、**遺伝子ごとの分散と検出率**が
実コントロール細胞と一致するように較正していた。a=1.0 で分散比 0.992、
検出率比 0.992 — どちらも 1% 以内で一致していた。**それでも間違っていた。**

採点側が回すのは Wilcoxon 順位検定で、これは分布の 2 次までではなく
**分布の形そのもの**を見る。2 つのモーメントを合わせても、形は合わない。

正しい較正基準は「実データと見分けがつかないこと」ではなく
**「予測がゼロなら排出は恒等写像であること」**。今の実装は構成上これを満たす:
予測が非ゼロの遺伝子だけを再抽出し、残りは実コントロール細胞をそのまま通す。
較正ではなく構造で保証されるので、以後この失敗は起きない。

## 3. ノックダウンが半分しか効いていなかった

同じ排出モデルに 2 つ目のバグ。平滑化の擬似カウントを
掛け算の**前に両側へ**足していたため、ノックダウンが希釈されていた:

```
誤: lam = (counts + a·L·m) · fc     → fc=0.15 のつもりが実際は 0.30
正: lam = counts · fc + a·L·m · max(fc−1, 0)
```

擬似カウントの目的は「その細胞でゼロの遺伝子も**上げられる**ようにする」こと
なので、上げる側にだけ効かせるのが正しい。初回提出の実測 on-target
log fold change は −0.84〜−1.15（意図は −1.20）で、この希釈と一致していた。

## 3b. 排出モデルのバグはもう 2 つあった

`scripts/null_emission_test.py` と `scratchpad/noise_cost.py` で測った。

### (a) 遺伝子を「引き直す」こと自体にコストがある

修正版は「予測が非ゼロの遺伝子だけ Poisson で引き直す」形だった。
効果ゼロ同然の fold change でも引き直すと:

| 引き直した遺伝子 | 偽陽性 DE | 向き |
|---|---|---|
| 0 個 | 0 | — |
| 1,500 個（lfc=0.001） | 203 | 86% が DOWN |
| 全 18,533 個（lfc=0.001） | **5,815** | **99.8% が DOWN** |

原因: 疎なカウントベクトルを Poisson で再抽出すると、カウント 1 の遺伝子が
約 37% の確率で 0 になる。**ゼロが増える方向に系統的に偏る**ので、
順位検定はこれを DOWN として拾う。

コントロール細胞は**すでに 1 回測定されたもの**なので、
そこにもう一度測定ノイズを乗せるのが誤り。既存のカウントを
**変換する**（確率的丸め）に変更。同じ検定で **0 件**になった。

実際のノックダウン応答は down 優勢なので、このバグは
**方向指標を不当に良く見せた**可能性がある — 一般化しない形で。

### (b) 擬似カウントが up-regulation を過剰配送していた

擬似カウントは「その細胞でゼロの遺伝子も上げられるようにする」ためのもの。
しかし**足し算**で書くと、どちらの向きに適用しても平均が狂う:

| 書き方 | 結果 |
|---|---|
| 両側に足す | ノックダウンが希釈（0.148 のつもりが 0.30） |
| 上げる側だけに足す | up-regulation が過剰配送 |
| **母集団レートへの混合** | **両方向で `E[lam] = fc · L · m`** ✓ |

過剰配送の症状: 排出した集団の有意遺伝子が **81〜86% が UP** になっていた。
実測 H1 署名の上位 200 遺伝子は **52% が UP** でほぼ均衡しているので、
これは明らかに排出側の偏り。混合形に直したところ、
向きの分布は 0.37〜0.96（標的ごと）と**モデルの予測を反映する形**になった。

```
w   = w0 · clip(1 − 1/fc, 0, 1)        # fc ≤ 1 では 0
lam = fc · ((1 − w)·counts + w·L·m)
```

`fc = 1` で `w = 0` になるので、恒等写像の性質は保たれる。

## 3d. 効果量は予測できる（`pds` の鍵）

300 署名の効果量 `||delta||` は 10 パーセンタイルと 90 パーセンタイルで
**8.2 倍**の開きがある。`pds` は L1/コサイン距離で順位を付けるので、
この大きさを当てられるかが効く。

| 予測子 | 相関（log 効果量に対して） |
|---|---|
| 標的遺伝子のベースライン発現量 | **−0.045（無効）** |
| STRING kNN による予測 | **+0.435** |
| 実験で回収された細胞数 | −0.584（2026 では固定 400 なので使えない） |

STRING 近傍が効果量を r=0.435 で当てられるので、
`magnitude_gamma=1.0`（近傍が示す効果量に完全に合わせる）が正しい。
掃引の結果と独立に一致した。

細胞数との強い負相関は、必須遺伝子ほど効果が大きく細胞が死ぬことを示している。
**DepMap の essentiality スコアは追加の効果量特徴になりうる**（未取得）。

## 3e. `pds` は効果量に一切依存しない — 100% 署名の「形」

`scratchpad/decompose_pds.py`

2026 の discrimination は `pds_cosine`、つまり**コサイン**距離での順位付け。
コサインは行ごとにスケール不変なので、効果量は原理的に効かない。実測でも:

| ホールドアウト | モデル | 真の効果量を与えた場合 | 真の方向を与えた場合 |
|---|---|---|---|
| H1 | 0.5910 | 0.5910（不変） | **1.0000** |
| H1test | 0.6093 | 0.6093（不変） | **1.0000** |
| H1val | 0.6268 | 0.6268（不変） | **1.0000** |

2025 の PDS は L1 距離で効果量に強く依存したが、**2026 は違う**。
`docs/03` に書いていた「効果量が PDS の鍵」は 2026 には当てはまらない。

したがって `pds` を上げる唯一の道は**署名の形を当てること** = 遺伝子表現の質。
oracle 類似度で discrimination 0.748 まで届く（§5）ので、
現在の 0.61 との差がそのまま残っている伸びしろ。

効果量そのものは `nmae` と DE 系指標には効くので、
`magnitude_gamma=1.0`（STRING 近傍が示す効果量に合わせる、r=0.435）は
引き続き正しい。

## 5. コントロール細胞の共発現は、トランス応答を予測しない

同じ 150 標的で 2 通り測った。**どちらも信号ゼロ。**

**(a) 共発現が直接トランス応答を予測するか**（`validate_on_2025.py`）

| | 値 |
|---|---|
| 予測 vs 実測トランス応答の相関（平均） | **−0.003** |
| 中央値 | −0.011 |
| 正の相関だった摂動の割合 | **44.7%**（偶然以下） |
| 効果量が大きい上位 1/4 に限っても | −0.008 |

**(b) 共発現が「署名の似ている遺伝子」を当てられるか**（`validate_knn_2025.py`）

150 標的を 1 つずつ leave-one-out し、残り 149 の実測署名を
類似度で重み付け平均して予測する。標的遺伝子自身は採点から除外。

| 予測子 | 平均 r | discrimination |
|---|---|---|
| 共発現 kNN | 0.165 | 0.509 |
| **平均署名（全摂動の平均を出すだけ）** | **0.188** | 0.500 |
| STRING kNN | **0.235** | **0.584** |
| oracle kNN（真の署名類似度・使用不可） | 0.471 | 0.748 |

読み取れること:

- **共発現 kNN は「平均署名を出すだけ」に負ける。** discrimination は 0.509 で
  ほぼ偶然。コントロール細胞の共発現には、どのノックダウンが似ているかの
  情報が入っていない。
- **モデルの形は悪くない。** oracle が r=0.471 / discrimination 0.748 に届くので、
  「測定済み署名の類似度重み付き平均」という枠組み自体は十分機能する。
  **ボトルネックは遺伝子表現。**
- **STRING（機能的相互作用ネットワーク）は本物の改善。** r 0.188→0.235、
  discrimination 0.500→0.584。GPU も学習も不要で、遺伝子カバー率 98.5%。
  ただし oracle の 0.748 にはまだ遠い。

2025 の上位陣が揃って「タンパク質埋め込みが効いた」と報告しているのは
この同じ穴を埋めていたからだと考えられる。次の投資先は遺伝子表現。

## 5b. 細胞株間転移は機能している（最重要の検証）

`scripts/cross_high_transfer.py`（実ファイル名 `scripts/cross_line_transfer.py`）

転移演算子は「文脈間で保存されるのは加算的な delta ではなく **fold change**」
という仮定に立っている。転移元が H1 一株しかない間、この仮定は
**一度も検証できていなかった**。

Replogle の K562（2,057 署名）と RPE1（2,387 署名）を scPerturb 経由で取得し、
片方の株だけから作ったライブラリでもう片方の株の実測標的を予測して採点した。
両株が測定した遺伝子だけに限定して比較している。

| ケース | pds | 方向一致率 | DE yield | jac |
|---|---|---|---|---|
| **株内** H1+H1val → H1test | 0.6087 | **0.7120** | 0.5671 | 0.1498 |
| 株間 K562 → H1test | 0.5808 | **0.6050** | 0.3912 | 0.0367 |
| 株間 H1×3 → K562 | 0.6178 | **0.6670** | 0.3128 | 0.0631 |
| 株間 K562 → H1 | 0.5993 | **0.6343** | 0.3843 | 0.0384 |

読み取れること:

- **`pds` はほぼ劣化しない**（株内 0.609 に対し株間 0.581〜0.618）。
  ノックダウン署名の「形」は細胞株をまたいでかなり保存されている。
  fold change による転移が discrimination については機能している、という直接の証拠。
- **方向一致率は株間でも 0.60〜0.67 を維持**。ベースラインは 0.511 なので、
  はっきり偶然を上回る。**転移そのものは正しい。**
- 劣化はほぼ **yield**（0.567 → 0.31〜0.39）と `jac` に集中する。
  つまり失っているのは「正しさ」ではなく「カバー率」— 実際に動く遺伝子のうち、
  こちらが主張できている割合が減る。

したがって改善の方向は「もっと多くの遺伝子について主張する」であって、
「予測を弱める」ではない。§1b の yield の教訓と一致する。

## 5c. 転移元の遺伝子カバー率が違うと平均が壊れる

公開 Replogle（scPerturb 版）は 18,533 中 **7,935〜8,246 遺伝子**しか持たない。
H1 は 12,200 前後。カバー率の違う署名を素朴に平均すると、
**測っていない遺伝子を「測定値ゼロ」として扱ってしまう**ため、
そこで予測がゼロに引き寄せられる。

K562 の 2,057 署名を素朴に足したときの実測: オフラインの scaled 合計が
**+0.931 → +0.039** に崩壊し、`jac` が 0.147 → 0.035 に落ちた。

対策を 2 段階で入れた:

1. `_consensus` のプーリングを遺伝子ごとに（そのソースがその遺伝子を
   測っている場合だけ重みを数える）。→ ほぼ変化なし。希釈は別の場所にあった。
2. **kNN の平均も遺伝子ごとに**（`coverage_aware_knn`）。近傍のうち
   その遺伝子を測ったものだけで平均する。→ +0.039 → **+0.494** に回復。
   `pds` はむしろ H1 単独より良くなる（0.6095 → 0.6130）が、
   `jac` はまだ 0.146 → 0.082 と戻りきらない。近傍プールが K562 に
   数で支配され、K562 が測っていない 10,600 遺伝子については
   寄与する近傍が少数になるため。

現時点の提出は **H1 単独**のライブラリを使っている。株を増やすこと自体は
`pds` に効くと分かったので、カバー率の扱いを詰める価値がある。

## 6. 転移元データの制約

| | 値 |
|---|---|
| 2025 公開データの遺伝子と 2026 の重なり | 18,077 / 18,533 |
| 2025 で摂動された標的と 2026 の 300 標的の重なり | **13 / 300** |

つまり **287/300 は直接転移できず、類似度による外挿に頼る**。
§5 の結論がそのまま効いてくる。

## 7. 環境上の制約（実測）

| | 値 |
|---|---|
| 提出物の stored entries | 2,059,467,763（上限の 43.4%） |
| 1 細胞あたり | 5,721（実コントロール細胞は 5,973） |
| 生 CSR としてのサイズ | 約 17 GB |
| gzip 圧縮後の h5ad | 4.30 GB |
| `.vcc` | 4.24 GB |
| `vcc prep` が必要とする常駐メモリ | **約 16 GiB**（CLI 自身の `sizing.py` の実測値） |
| この環境の RAM | 15 GB |

`vcc prep` はこの環境では動かない。密度を下げれば動くが、それは
実コントロール細胞より浅い細胞を出すことを意味し、DE の検出力を
ローカルの都合で捨てることになる。そこで `.vcc` を直接書き出し、
**本物の `vcc prep` との一致をテストで保証**している
（`tests/test_vcc_parity.py`: 小規模な提出物を両方の経路に通し、
アーカイブから戻る AnnData が一致することを確認）。
