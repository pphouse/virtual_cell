## 2. 絶対に知っておくべき事実

### 2.1 データの落とし穴 — 12 回分の提出を無駄にした原因

`ReplogleWeissman2022_K562_**essential**.h5ad`（1.55 GB、2,058 摂動）と
`..._K562_**gwps**.h5ad`（genome-wide、9,867 摂動）は**別物**。

| ライブラリ | 本番 300 標的のカバー率 |
|---|---|
| essential | **25 / 300** |
| **genome-wide** | **272 / 300（91%）** |

チャレンジは**非必須遺伝子**を選んでいる。必須遺伝子スクリーンに無いのは当然。
`docs/06` に書いた「2026 パネルは Replogle と 1 つも重ならない」は**手元のファイル 1 つの話**で、
そこから派生した推論（「全部外挿するしかない」「オラクル類似度でも 0.748 が天井」）が全部倒れた。

**単一細胞版 8.8 GB は不要。** 疑似バルク `K562_gwps_raw_bulk_01.h5ad`（375 MB、
figshare article 20029387）で足りる。**`normalized` ではなく `raw` を使う**
（normalized は対照に対する z で、対照の分散 0 の遺伝子に inf が入る）。
取り込みは `scripts/build_library_gwps.py`。

### 2.2 採点の構造

Overall = **6 メンバーの単純平均**（`pds` / `expr_mse` / `nmae` / `fid` / `reach` / `jac`）。
採点器は公開されている（`ArcInstitute/cell-eval2`、`rule_version` 3）。

* **`expr_mse` は 484 件中 455 件が 0**。自分も 0。生値は「小さいほど良い」MSE で、
  上位は 0.83、自分は 4.06。**丸ごと 1 メンバー捨てている。** 未着手の伸びしろ。
* **`fid` は `max(n_pred, n_real)` で、`jac` は和集合で割る** —— 宣言数そのものが採点対象。
* **`nmae` と `pds` は 484 件で相関 −0.241**（生値なので「両立している」の意）。
  **予算を広げると `nmae` が壊れる**（v23 で −0.1042 で全利得が飛んだ）。
* 本番の平均 `n_real` ≈ 275（v8 が `J_p = n_real/n_tested` を使って買った数）。

### 3.2 装置 — ここが一番の資産

**H1 排出（本番 Overall の代理）**:
```
scripts/build_local_context.py --source <検証分割> --max-perts 60   → ref_h1_s60.h5ad
scripts/local_reference_de.py  --adata ref_h1_s60.h5ad             → de_ref_h1_v45.parquet
scripts/local_predict.py  ... --out pred.h5ad
scripts/local_score.py --reference ref_h1_s60.h5ad --prediction pred.h5ad \
    --de-real de_ref_h1_v45.parquet --pds          # --skip-de を外すと全メンバー
```
出力の最終行に **`sum_scaled/6`** が出る。これが本番 Overall の代理。
1 腕 ≒ 17 分（予測 8 分 + 採点 9 分）。**`n_real` 中央値 203**（本番 ≈275）。
**DE 真値は参照と対で作ること**（別分割の真値とは標的が 1 つも重ならない）。

**v25 構成の基準値**: `pds` 0.6343 / `fid` 0.4938 / `reach` 0.1233 / `jac` 0.0760 /
`nmae` 0.9903 / **`sum_scaled/6` = +0.0231**（シード 1 は +0.0203）。

**K562/RPE1 パネル（`pds` 専用）**: 1 腕 5 分。換算率は **パネル scaled pds × 0.36**
≒ 本番 `pds` メンバー差（3 点で 0.42 / 0.28 / 0.37）。
**`nmae` には絶対に使わない**（本番と逆を指す。RPE1 の `n_real` は 462 で本番の 275 から遠い）。

### 3.3 判定規則

* 大きな変更（特徴ブロックを足す等）: 対の差の sd 0.010〜0.012。**1 シードで 0.02 未満は読まない。**
* つまみを少し動かす: 対の差の sd 0.0027〜0.0045。3 シードなら 0.005 が読める。
* **必ず同一シードで対を取り、複数シードで符号が一致してから枠を使う。**
* **片株・片シードだけの山は 4 回外した**（§17・§25・§31・§40 直前の `confidence_prior`）。

## 5. 他チームは何をしているか（説明文から）

`data/leaderboard_2026-08-31.csv` の `description` 列に 172 件の自己申告がある。頻出する要素:

* **複数の摂動スクリーンを合成**: Replogle GWPS + **X-Atlas HCT116** + **HEK293T** +
  **primary CD4（Rest/8h/48h）** + Tian CRISPRi。**inverse-variance 重み**で統合。
* **pseudobulk log2FC の転移**（「delta transfer」「exact pseudobulk transport」）
* **Gram whitening / SVD**（「4-source perturbation-mean + SVD10 + Gram whitening」）
* **STATE**（Arc 公式モデル）を素で出した「STATE baseline」が **2 位（+0.1894）**。
  「E010 0.6 E005 + 0.4 STATE-SE」のようにブレンドしている例もある。
* LLM 路線もいる（「PertMind: Eliciting Emergent Biological Reasoning in LLM via RL」+0.1519）

**最重要**: **公式ベースラインの STATE を素で出すだけで自分の 4 倍以上**。
AI モデル路線に切り替えるなら、**まず STATE を動かして基準線を取る**のが最短。

## 6. AI モデル路線への提言（DGX Spark 前提）

### 6.1 まずやること（順番に）

1. **STATE を動かして提出する。** 公式実装があり、リーダーボードで +0.1894 の実績。
   これが取れれば現状の 4 倍で、以後の改善はここを基準線にできる。
   **手元の H1 装置でそのまま採点できる**（`sum_scaled/6` が出る）。
2. **STATE の出力を、いまの予算付き排出器に通すか通さないかを測る。**
   `jac`・`fid` はいまの排出器が上位陣と互角の水準を出している（0.0299 / 0.5048）。
   モデルの生出力より、モデルの delta を排出器に食わせたほうが総合で勝つ可能性がある。
   `src/vcc2026/budget.py` の `BudgetedPredictor` は delta を受け取る形になっている。
3. **`expr_mse` を取りに行く。** 484 件中 455 件が 0 で、上位は +0.17。
   ここは学習ベースなら素直に効くはず（絶対発現量の予測）。**単独で Overall +0.028 相当。**

### 6.2 学習データ

**手元にあるものだけで、かなりの規模が組める:**

| 出所 | 摂動数 | 細胞株 |
|---|---|---|
| Replogle GWPS | 9,867 | K562 |
| Replogle essential | 2,058 | K562 |
| Replogle RPE1 | 2,394 | RPE1 |
| 2025 VCC 訓練データ | 300 | H1 |

**足すべきは X-Atlas（HCT116 / HEK293T）** —— 上位陣が使っている。
ただし figshare 29190726 の単一細胞版は **209 GB / 350 GB** で、疑似バルク版が見当たらない。
DGX Spark のストレージ次第。**まず疑似バルク版が別途公開されていないか探すこと**
（Replogle も単一細胞 8.8 GB ではなく疑似バルク 375 MB で足りた）。

### 6.3 落とし穴（AI 路線でも同じ）

* **検証は必ず H1 装置で。** 手元の代理で改善が見えても、
  **RPE1 パネルは `nmae` について本番と逆を指す**。装置の領域（`n_real`）を必ず確認する。
* **リークに注意。** GWPS を学習に使い、本番 300 標的の 272 がそこにある。
  「予測できている」のか「引き当てている」のかを区別する検証設計が要る
  （`--holdout-target-signatures` はそのために作った。ただし**本番の模擬としては誤り**——
  本番は 267/300 が実測を持つ）。
* **提出は 1 日 2 回。** アップロード 7 分・採点 20〜60 分。
  落ちたら `vcc submit --resume --wait`（枠は消費されない）。
* `.vcc` は 4.3 GB。ビルド 30 分・ピークメモリ 8 GB 程度。

### 6.4 未解決で、いま一番おいしそうなもの

* **`expr_mse`**（1 メンバー丸ごと 0。上位は +0.17）
* **摂動後の時点が不明。** 配布データにも公開資料にも**採取までの日数が書かれていない**
  （Cell 論文の Methods は 403 で読めず）。Replogle GWPS は増殖スクリーンとして
  数日〜1 週間の時点、10x Flex の本番がもし早い時点なら応答の大きさが系統的にずれる。
  **機関アクセスがあれば Cell の Methods を確認する価値がある。**
* `confidence_prior`（実測をどれだけ信用するか）: シード 0 で +0.0038、シード 1 で −0.0006 と
  **符号が一致せず未決着**。3 シード目が再起動で流れた。

## 7. コードの地図

```
src/vcc2026/
  budget.py       予算付き呼び出し集合。排出される大きさは発現量で決まり、
                  モデルの delta は符号と順位にしか使われない（§37・§38 の理由）
  model.py        CCDT 転移。delta = alpha * M * [b*D + (1-b)*K]
                  b = w/(w+confidence_prior)。本番は 267/300 で b≈1（D 腕）
  library.py      SignatureLibrary（疑似バルク署名の器）
  coessentiality.py  DepMap 共必須性 + blend()。**入れ子で重みが等分にならない**

  proximity.py    CRISPRi の近傍サイレンシング（効いている証拠は無いが害も無い）
  writer.py       ストリーミング h5ad ライタ（4.3 GB を書く）
  vccfile.py      .vcc パッケージャ（公式 vcc prep と一致確認済み）

scripts/
  build_library_gwps.py   ★ genome-wide 取り込み（--restrict-to で 300 標的に限定）
  build_local_context.py  ★ H1 参照の作成
  local_reference_de.py   ★ DE 真値の計算
  local_predict.py        ★ 手元予測
  local_score.py          ★ 手元採点（--skip-de を外すと全メンバー）
  predict_vcc2026.py      ★ 提出物のビルド
  panel_score.py          K562/RPE1 パネル

tests/  40 件。4 細胞株の CRISPRi シミュレータ（チャレンジデータ不要）
data/leaderboard_2026-08-31.csv  484 件のスナップショット
```

## 8. この案件から得た一般的な教訓

1. **装置を 6 回間違えた。** 代理指標・摂動数・モデル設定・採点していた領域・
   装置自身のノイズ・`nmae` の株選び。**改善より装置の検証に時間を使うべきだった。**
2. **「効かない」という結論は前提つき。** `n_components` は
   「採用しない」→「そもそも効かない」→「頂点 200 で最大の利得」と 3 回変わった。
   測定は 3 回とも正しく、変わったのは前提。**結論と一緒に前提を書き残すこと。**
3. **データを疑うのが最優先。** 15 節分の解析と 12 回の提出が、
   ファイル 1 つの取り違えの上に乗っていた。
   **他人の説明文（リーダーボードの `description`）が一番安い検証手段だった。**
